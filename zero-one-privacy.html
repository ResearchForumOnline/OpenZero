ZERO ONE Desktop privacy notice

Updated 30 September 2026. The 8.1.0 additions described here are a release candidate; this notice does not establish Microsoft Store certification, public availability or installation. ZERO ONE 8.0.0 remains covered by the unchanged AI, browser and diagnostic boundaries below. Earlier releases may have different features and legacy connected services.

Your notebook and ZeroThink workspace are stored on this device. ZNotes and ZeroThink require no publisher-hosted account or automatic cloud sync. Optional AI, web search and browser features contact the runtime, provider or sites you choose.

ZNotes and private credentials

ZNote titles, text, timestamps, pins, labels, colours, checklist items and archive/trash state are encrypted before being saved in the app's user-data folder. The 8.1.0 candidate automatically encrypts new notebooks with two nested AES-256-GCM layers using two independently generated 32-byte keys. Each layer uses a fresh random nonce and authentication tag; authenticated data binds the notebook identifier, save generation and layer. Each key is separately wrapped with operating-system-backed Electron safeStorage and saved in the notebook's fixed .keys folder in app data. Both keys are unlocked by the same operating-system account. This is not two-factor authentication, separate-party key custody or the Microsoft Double Key Encryption service. It does not protect against an attacker controlling your unlocked account.

The candidate adds automatic saving of edits, checklists, labels, colours, pins, Archive and Trash. An existing version-1 OS-encrypted notebook remains readable and upgrades on its first successful save: the app preserves the original encrypted file as .legacy-v1.bak before atomically replacing the notebook with the version-2 dual-key format. If secure storage is unavailable, the app refuses plaintext storage; insecure Linux basic_text fallback is rejected. Notes are not automatically uploaded, synced or included in diagnostics. OpenZero tokens and optional Assistant and Serper API keys are also stored only when secure credential storage is available. Content is decrypted for display in the app, and a selected remote service receives only the content you choose to send to it.

Importing a ZNotes JSON export is an explicit local file-picker action. Imported notes are saved into the encrypted notebook with new identifiers; existing notes are retained. Exporting notes requires an explicit plaintext warning and a save location. The JSON export is readable, is not an encrypted backup, and includes the stored notebook's active, archived and trashed notes, labels and checklists. Keep exports in a protected location and remove them separately when no longer needed.

If you back up app data with operating-system or other file-copy tools, keep the version-2 encrypted notebook and its two OS-wrapped key files together. Those keys remain tied to compatible operating-system account protection; copying them is not a universal recovery method or a promise that another account or device can open the notebook. The encrypted legacy backup and any manually copied backups can retain older note contents even after you delete notes in the app.

Optional AI: local, self-hosted or API

You can configure a local Ollama model, your own OpenZero runtime on this computer or a remote server, or an optional OpenAI/Groq API for Assistant chat. Model prompts and conversation context are sent to the chosen endpoint. A remote runtime or API therefore receives that content and network request metadata under its own privacy, retention and billing terms. Local model chat does not provide the full OpenZero orchestration or Browser Pilot planner. The app checks reachability of your configured OpenZero address; the server can receive your network address and request metadata from these probes. The isolated OpenZero workspace retains its cookies, cache and site storage on this computer.

ZeroThink Studio and local research

ZeroThink is included locally in ZERO ONE. It requires no hosted login, admin account, publisher subscription or company database. You explicitly select UTF-8 text files or individual ZNotes as sources. The 8.1.0 candidate stores chat titles, messages, public work summaries, saved research results, pins, source references and the selected document library in an operating-system-encrypted workspace in the app's user-data folder. These saved chats and sources survive app restarts; closing the app does not delete them. Secure storage is required, with no plaintext fallback. In 8.0.0, unsaved ZeroThink research was session-only.

Persona settings and remembered facts you explicitly enter are saved in that encrypted Studio workspace. When you run Chat or Research with a model, the app automatically includes the saved persona and the latest five remembered statements in that selected model's context. Offline research does not send them anywhere. Memory is not automatically extracted from your files or chats, and your saved statements are not independently verified facts. You can edit or remove them in Persona & memory; copies already sent to a remote provider are governed by that provider's practices.

File imports support TXT, Markdown, CSV and JSON, up to eight files per selection, one MiB each and two MiB total. The saved library can hold up to 32 selected documents with a two MiB text limit. Importing a source copies its selected text into the local workspace; removing that copy does not alter the original file or ZNote.

Offline evidence maps use local deterministic retrieval without a model or network request. Optional model mode sends the question, bounded recent conversation, retrieved source excerpts and bounded draft/review context only to your selected OpenZero server, OpenAI or Groq provider. Direct editions also support existing local Ollama. There is no automatic cloud fallback or automatic upload of the full notebook or library. A remote provider can process and retain the content it receives under its own terms. Stop or Escape aborts the active request and future stages; it cannot retract content already received by the provider. The research engine does not automatically browse full pages, execute generated commands or change model weights.

Zero mode can ask the selected model for a short public work summary alongside its answer. It is an explanation generated by that model, not a private scratchpad, independent agent result or scientific verification. Research exports are readable Markdown or JSON files, and saving a report to ZNotes uses operating-system encryption. Diagnostics exclude ZeroThink source titles/text, questions, chats and reports. Source-ID checks show that referenced excerpts are present; they do not establish scientific truth.

Optional Serper web search

The 8.1.0 candidate adds optional Search web and Automatic web research controls using your own Serper API key. A manual Search web request sends your query to Serper, with the key in the request header and ordinary network request metadata. Automatic web research is off unless you enable it. When enabled for a model run, your chosen model receives the research question and decides whether to generate a public search query; the app then sends that query to Serper without a separate approval for each search. The planner is instructed to exclude private facts and identifiers, but generated queries can reflect information in your question. Avoid including private material in requests where you enable automatic search.

The Serper request contains the query rather than the full chat history, notebook, persona, remembered facts or document library. Serper processes it under its own privacy, retention, quota and billing terms. The key is encrypted locally when saved and is not returned to the renderer settings bridge or included in diagnostics. Search returns up to three labelled snippets and source links, not full-page downloads. Automatic snippets enter the active run and can appear in its saved answer or evidence report; manually selected library snippets are stored in the encrypted workspace. Using snippets in a model task sends retrieved excerpts to that task's chosen provider. Opening a source link in your browser sends an ordinary web request to that site.

Native Agent mode

The 8.1.0 candidate adds native Agent mode for a project folder you explicitly choose. The app's included Node executor can list, search and read project files, propose full-file writes, and propose commands. Your request, selected folder path, file names and retrieved project content, recent task history and bounded tool or command results are sent to the model/runtime you select. File writes and commands require approval; review the full proposed command before approving it. Commands start with the selected project as their working directory but run with your operating-system account's permissions: the working directory is not a sandbox, and an approved command can access files outside that folder, use the network or change other local data. The loop has step, response-size and time limits and a stop control, but stopping cannot reverse completed changes, remote requests or side effects. Agent progress and tool logs are shown in memory and are not automatically saved to the encrypted Studio history. Native Agent mode is separate from the isolated Browser Pilot tab and its page-control approvals.

Browser Pilot

Browser Pilot controls only the isolated tab you explicitly grant for one bounded task, with a 12-step limit and a stop-and-revoke control. Visible page text, headings and interactive-control metadata are sent as a compact structural snapshot to your configured OpenZero planner. The snapshot omits form values, passwords, payment details, secret fields, file selections and CAPTCHA values, strips URL queries/fragments and redacts long token-like path segments. The task request and proposed actions may also contain information you deliberately supply. A remote runtime receives that task and page context. Cross-site navigation, personal-data typing and consequential actions pause for approval. Ordinary page visits send normal web requests to the sites you open.

Pilot snapshots and task history are not written to disk. Current run state and up to eight short step results remain in memory until the run ends. Pilot browser cookies and site storage persist until you clear desktop data. Camera and microphone access are denied in embedded workspaces.

Local ZSEC scans

ZSEC Shield scans a folder only after you choose it and request a scan. There is no automatic background scan, sample upload, deletion or quarantine. Local scan reports can contain paths, file hashes, rule matches and errors. They remain on your computer unless you share them.

Diagnostics and updates

Diagnostics export runs only when you request it and choose a location. It includes app/platform version, machine-health totals, configured OpenZero origin and reachability, preferences and whether credentials are configured. It excludes credential values, note contents, prompts, conversation text, cookies and URL credentials, paths, queries and fragments. Review an export before sharing it. Update checks contact the official GitHub repository. Microsoft Store editions use Store update delivery; direct desktop editions have their own verified-update flow.

Retention and removal

Archive and Trash retain notes in the encrypted notebook. Restore returns a trashed note to the active notebook; Delete forever removes it from the current notebook after confirmation. It does not remove the migration's encrypted .legacy-v1.bak or manually created app-data backups. In ZeroThink Studio, delete saved chats, remove selected library sources or edit/remove persona and remembered facts individually. Removing a library source does not remove excerpts already included in saved chats, reports or exports. Deleting app records is not a universal purge or a promise of secure erasure.

Clear desktop data retains both your encrypted ZNotes notebook, its protected key files and legacy encrypted backup, and your encrypted ZeroThink Studio chats, library and personalization. After confirmation, it clears settings, encrypted credentials, saved workspace logins and browser/runtime session storage. The Store edition also clears app-local ZSEC state. Delete notes, chats and library sources in their respective workspaces when you want to remove those current saved records. Exported notes, research reports, diagnostics and separately copied backups remain at the locations you chose. Uninstalling may also retain app data. Remote accounts and copies held by providers are governed by those providers; clearing desktop data does not delete them. Maintain your own backups.

Retired integrations

The 7.9.6 update removes hosted mail, video-call and research-account routes, sign-in controls and their background probes. It provides on-device ZNotes and user-configured AI. Earlier releases may still show retired service controls.
