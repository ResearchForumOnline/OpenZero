ZERO ONE Desktop privacy notice

Updated 3 October 2026. This notice covers retained ZERO ONE behavior and the 8.4.0 source update. Source, GitHub installers, Microsoft certification, Store availability and installation are separate states; this notice does not establish their release status. Earlier versions may have different features and connected services.

Your notebook and saved ZeroThink workspace are stored on this device. Local features require no publisher-hosted login, account database or automatic cloud sync. Optional model, search, quantum and browser workflows contact the service, runtime or sites you choose and can transmit content under those destinations' terms.

ZNotes and local encryption

ZNote titles, text, timestamps, pins, labels, colours, checklists and archive/trash state are saved in an encrypted notebook in app data. The format introduced in 8.1 uses two nested AES-256-GCM layers and two independently generated 32-byte keys. Fresh nonces and authentication tags bind the notebook identifier, generation and layer. The two keys are separately wrapped by operating-system-backed Electron safeStorage in the notebook's fixed .keys folder. Both keys are unlocked by the same operating-system account. This is not independent two-factor or separate-party custody, Microsoft Double Key Encryption, or protection against someone controlling your unlocked account.

Edits autosave after a short delay and on transitions; forced termination or power loss can lose pending edits. Existing version-1 encrypted notes remain readable and migrate on their first successful save, retaining the original encrypted .legacy-v1.bak before atomic replacement. Corrupt/missing-key notebooks fail closed. Secure OS storage is required and insecure Linux basic_text is refused, with no plaintext fallback. Notes are not automatically uploaded or included in diagnostics; a note explicitly selected for a model task can be sent to that model.

ZNotes JSON import is a local native-picker action with validation and fresh note identifiers. Explicit JSON export is readable, unencrypted, and includes active, archived and trashed notes. If you copy app data as a backup, keep the notebook and both OS-wrapped keys together; account-bound keys are not a universal cross-device recovery method. Migration backups and separate copies can retain older contents after note deletion.

Private API Vault and selected AI

The native Vault holds up to 64 named Vault profiles across 11 integrations. Eight chat choices are Groq, OpenAI, Google Gemini, Anthropic Claude, xAI, NVIDIA NIM, Featherless and your OpenZero/compatible server. Serper supplies search, and IonQ/IBM supply quantum services. Profile names, provider, endpoint, model, timestamps and entered keys are saved with OS encryption in a separate Vault file. Origins/names may identify private infrastructure. Saved key values are decrypted only in the main process and accompany requests to the service needed for the operation; renderer reads expose metadata and key-presence flags, not saved keys. Diagnostics exclude key/token values.

The selected chat profile supplies Assistant, ZeroThink Chat, Research, native Agent and Browser Pilot planning. If none is active, the app-selected provider/runtime is used. Remote requests send prompts, bounded conversation/source/project context, chosen model and response parameters to that endpoint. A remote service can process and retain them under its privacy, retention, quota and billing terms. No publisher key/account, guaranteed free-token allowance or automatic quota failover is supplied. Direct editions retain optional legacy Ollama; the 8.3 built-in CPU engine supports Store and direct packages.

Legacy encrypted settings credentials migrate into the Vault before old fields are removed. Failed decryption/import preserves original bytes and reports an error. Unrelated preference saves retain an existing selected Vault profile. Confirmed Clear desktop data can reset damaged legacy credentials while retaining recovery copies as described below.

Built-in OpenZero CPU AI

The 8.3 package includes a pinned official llama.cpp CPU engine. After you review and accept the separate Google Gemma and OpenZero model terms, CPU setup downloads about 3.42 GB of model data from the publisher's pinned Hugging Face revision, following checked HTTPS CDN redirects. Hugging Face and its CDN receive the request metadata, including your IP address. Downloaded weights are stored under the app's local user-data directory and verified by exact size and SHA-256 before use. Setup can be cancelled or retried; no model is silently downloaded at first app launch. The weights' terms are separate from the app's Apache license.

The app launches only its owned CPU inference process, on an authenticated random loopback port with no browser UI or public listener. Local prompts and generated responses stay on this device in this mode. Explicit web searches, browser navigation and remote profiles still contact their selected services. The app does not upload the local model, train or rewrite its weights. Release model memory stops the owned process; downloaded data remains for subsequent use. At least 8 GB RAM and model storage plus temporary free space are required. CPU generation can take minutes on older hardware; Stop aborts the active request.

Saved ZeroThink Studio and sources

Studio conversations, titles, pins, public work briefs, reports, source references, library copies, persona and explicit remembered facts persist in a separate OS-encrypted local file. They survive restart. The saved persona and latest five explicit statements enter selected-model context when a model run uses them; offline maps send nothing. Facts are not automatically extracted from your chats/files or independently verified. Removing a library source does not remove excerpts already saved in chats, notes or exports.

The library holds 32 selected documents and two MiB of text, with eight selected sources per run and one MiB text per source. TXT, Markdown, CSV and JSON import locally. The PDF import accepts up to ten MiB, 100 pages and one MiB extracted text per document. A bounded local worker extracts text with page labels without uploading the original or fetching its external resources. Encrypted/corrupt PDFs and scans without extractable text are rejected; OCR is not bundled. Source import copies chosen text into encrypted Studio and does not alter the original file or ZNote.

Offline evidence maps use deterministic local retrieval. Model runs send the question, retrieved selected excerpts, bounded recent conversation/draft/review context and explicit profile to the chosen model. Stop/Escape aborts active requests and future stages but cannot retract content already received remotely. Zero mode requests an inspectable public approach brief, not private model scratchpad or independent scientific verification. Source-ID checks identify existing excerpts; they do not prove scientific truth. The 8.4 deterministic claim review can record prose units, unknown references, numeric discrepancies and SHA-256 fingerprints of the exact selected excerpts and answer. Draft review issues may enter the selected provider's revision context. The saved/exported Markdown includes the claim ledger and fingerprints; these do not authenticate publishers or prove truth or entailment.

Markdown, JSON and PDF research exports are readable and unencrypted at the path you choose. They may contain private excerpts, supplied notes and model drafts. Export does not publish or validate them. Saving a result to ZNotes uses notebook encryption; external exports require separate retention/removal.

Research Workbench

The workbench provides thirteen built-in workflows and up to 32 custom templates, with visible stages, source requirements and checks. Custom names, descriptions and instructions are encrypted in a separate local file with queued atomic writes. Paper Creator/scenario fields remain in current form memory. The 8.3 research-project library separately autosaves up to 32 named research projects, including questions, process choices, selected source text, run status and latest results, in an OS-encrypted local file. Interrupted runs reopen for review without automatically contacting a model or resuming execution. Portable project JSON import/export includes readable question/source/result content; it excludes Vault credentials and device configuration, but user-supplied content may itself contain private facts. Preview is deterministic and local. Continue to Research places the prepared question in the composer; sending with a model sends its supplied notes and selected excerpts to that provider. User statements are not independently verified. The module does not invent citations, authorship, experimental results or calibrated probabilities.

Optional Serper search

Manual Search web sends your query, service key and ordinary request metadata to Serper. Automatic web research is off until enabled. When enabled, a bounded decision by the selected model can generate a public search query from your request and send it without a separate approval for each search. The query can reflect private details despite instructions to avoid them; avoid private material when enabling automatic search. The query, rather than the full notebook/library/persona, is sent to Serper. Its processing, retention, quotas and billing follow its terms.

Search returns up to three labelled snippets/source links, not full-page downloads. Automatic snippets can enter the saved answer/evidence report. Manually selected snippets can be saved in encrypted Studio; using them as sources sends retrieved excerpts to the chosen model. Opening a source link sends normal browser requests to that site.

Local and cloud quantum workflows

The 8.2 native local simulator executes bounded ideal classical statevector calculations without credentials or network requests. Sample counts use a seeded pseudorandom generator and are reproducible. It demonstrates no physical hardware, quantum advantage or change to model weights.

Optional IonQ operations use your own Vault key at https://api.ionq.co/v0.4. Backend/job/status/result/cost/estimate requests exchange ordinary metadata and requested account records. Confirmed submission sends the displayed circuit, backend, shots, name and settings. Cloud simulator submission needs confirmation. Hardware needs a fresh matching circuit/backend/shots/key estimate, review ceiling and explicit acknowledgement that actual charges may exceed the estimate. The ceiling is not a provider-enforced spending cap. Submitted remote jobs and charges can continue after Stop or closing the app. Cancellation is explicit and cannot guarantee charges are avoided. No owner grant credentials or restricted grant results are bundled.

IBM discovery sends your IBM key to https://iam.cloud.ibm.com/identity/token, then uses the bearer token and entered instance CRN for read-only backend/status queries at the official selected us-east or eu-de Quantum API. CRN/region/results remain in current form memory unless explicitly copied/exported, and require re-entry after restart. No IBM hardware jobs, instance creation or Qiskit installation are provided. These providers can retain account/request information under their own terms.

Quantum reports exclude key/token values. They remain in the current workspace until exported or explicitly added to encrypted Studio Library; selected report excerpts can then enter a subsequent model request. They are not automatically sent to a chat model. Cloud jobs do not run the language model on quantum processors, and public probabilities must not be used as secret encryption keys.

Native Agent and Browser Pilot

Native Agent operates on a project folder you choose. The request, path/file names, retrieved contents, recent tool history and bounded command results go to the selected model. File tools reject outside-project paths, links and common secret files. Targeted edits require a unique literal match and unchanged source digest before replacement. Proposed writes and commands need review and approval. Commands use normal OS permissions, so a selected working directory is not a sandbox and approved commands can affect outside files/networks. Step, time/output limits and Stop cannot reverse completed side effects. Progress and tool logs remain in memory unless you copy them; this does not rewrite model weights.

Browser Pilot uses a separate isolated tab granted for a bounded task, with a 12-step limit and Stop/revoke. The selected chat model receives task/model, compact visible text/title/headings, redacted URL, viewport, interactive-control labels/metadata and up to six short prior results. Form values are omitted; URL queries/fragments and long token-like path segments are redacted. Visible text/labels may still contain private data. Identified passwords/payments/secrets/file/CAPTCHA fields are blocked, and cross-site/personal/consequential actions pause. Structural detection is not infallible. Ordinary navigation sends requests to sites you visit.

Pilot snapshots/task history are not written to disk. OpenZero and Pilot browser partitions retain cookies/cache/site storage until cleared. Embedded camera/microphone access is denied. Optional saved workspace logins require explicit opt-in and secure encryption; filling them requires a user request on the approved runtime origin.

Probes, ZSEC, diagnostics and updates

The configured OpenZero address receives a bounded reachability GET on launch, every 30 seconds, manual refresh and diagnostic export, with a version user-agent, redirects and 6.5-second timeout. Remote servers receive network/request metadata even when a panel is closed. Local selected-folder ZSEC scanning starts only after you request it. Reports/state can contain paths, hashes, matches and errors. No automatic sample upload, background scan, quarantine/deletion or real-time protection is claimed.

Requested diagnostics export saves local JSON with app/platform/system totals, configured runtime origin/reachability, preferences and credential-presence flags. It excludes keys/tokens, note/source/chat/page contents, prompts, responses, cookies and URL credentials/paths/queries/fragments. Origins can identify private servers. The app does not send the export automatically. Update checks contact official GitHub; Store updates use Microsoft delivery, while direct editions have verified-package update controls. External support/setup/report links use the user's browser and destination practices.

Retention and confirmed reset

Archive/Trash retain notes; confirmed Delete forever removes records only from the current notebook. Migration backups, exports and other copies may retain older contents. Delete Studio chats, library items and explicit facts in their workspaces; copies already sent to providers follow provider terms.

Clear desktop data is a reset, not universal erasure. Before removing current settings and Vault files, it preserves their original bytes in local sibling .recovery-UUID files. Vault recovery files remain encrypted; settings recovery copies retain original preferences and any encrypted legacy fields. The action clears current settings/Vault, saved workspace logins, browser/runtime session storage and Store-local ZSEC state, then restarts. It retains encrypted ZNotes, wrapped notebook keys/legacy backup, encrypted Studio, research-project library, custom templates and downloaded local model files. Recovery files, exports, diagnostics and manually copied backups remain and need separate removal if desired. It does not erase remote accounts, provider data or submitted jobs.

The direct installer retains app data on uninstall; final Store-signed uninstall behavior requires Windows verification. No universal secure-erasure promise is made. Maintain your own backups. Hosted ZMail, CallChat, DNA/admin/payment integrations and company account databases are excluded from current local features.
